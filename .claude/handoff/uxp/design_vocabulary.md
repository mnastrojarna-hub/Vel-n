# 1 · ONE APP-WIDE VOCABULARY (gesture · motion · display)

Source of truth = approved design (DESIGN_V22 → V21 → V2 → appdesign_spec v1 "v1") + boards. Where the spec is silent the rule is marked **[gap → platform]** and uses existing MgMotion tokens only. Every v2 screen, sheet, dialog and overlay follows these rules; a package may not invent another value.

## G · Gestures
- **G1 Tap first.** Every tappable = `MgPress` (cards/rows scale .97, discs/icons .92, 150 ms ease) + `selectionClick`; hit area ≥ 44 px (v1 §2.7 `press`, V2 §1.3, V22 §6.1). Every swipe below has a visible tap twin (owner: tap = swipe, never a swipe-only action).
- **G2 Back / close** (V22 §6.1–6.2). One control `MgV2Back` 44 px: screens top-left (16, 55), sheets top-right inset 12; style by surface (photo `night@.8`+ring, dark `white@.10`, light white+line); stays pinned when the header collapses (`MgPage.pinnedBack`). Per screen type exactly as V22 §6.2 (tab root none + origin chip; pushed ‹; focused flow ‹ + existing T6 discard; live full-screen ‹ keeps the process; viewer ✕; result ✕ → defined destination; sheet ✕ + grabber + swipe-down + scrim; dialog = safe button). System back = the visible control.
  - **iOS** edge swipe works on every pushed page (Cupertino transition — kept even under reduced motion because it carries the gesture). On guarded pages with in-screen steps (`PopScope(canPop:false)`: register, reset, reservation edit intents) `MgEdgeBack` forwards a left-edge swipe (20 px strip, commit 30 % width or 700 px/s) to the SAME `onBack` the ‹ runs **[gap → platform]**.
  - **Android** predictive back on every pushed page (`PredictiveBackPageTransitionsBuilder`, manifest already `enableOnBackInvokedCallback=true`); guarded pages show no preview and run their existing confirm **[gap → platform]**.
- **G3 Sheets.** Light by default (R5.10). Grabber 42×5 + ✕ 44 + swipe-down + scrim tap (V22 §6.2, T2 §5.2). Swipe-down works from grabber/header AND from the body when the body is scrolled to the top **[gap → platform]**; commit at 25 % of sheet height or 700 px/s, else spring back 300 ms emphasized. Dirty form → existing T6 through `PopScope` (`maybePop`). Non-dismissible sheets (SOS report, payment in flight, terminal payment errors) have no grabber and ignore drags. Snap points only where they exist today (place sheet 50–97 %). Max height 86 %, body scrolls, footer buttons pinned.
- **G4 Horizontal swipes — only these:**
  - (a) photo pagers that show dots / counter (catalog card segments, bike detail hero, product photos, POI sheet, photo viewers): swipe = next photo.
  - (b) segmented in-place content where the board shows it: Rezervace filters (Reservation board "Přejetím prstem přepneš filtr"), Zprávy notes/threads, Moje sub-tabs — `MgSwipeSegments`: content follows the finger ×0.35 (×0.15 at the ends), thumb tracks the drag, commit at ≥ 72 px or ≥ 450 px/s → `selectionClick` + directional switch; else spring back (300, `MgMotion.spring`) **[gap → platform]**.
  - (c) TripCalendar month: fling ≥ 450 px/s = ‹ / › **[gap → platform]**.
  - (d) sibling pagers that already exist (bike detail, ride detail, route detail, place sheet) — always with the board's visible "‹ n / m ›" control.
  - (e) carousels snap to whole cards with a 24–48 px peek (Home routes, routes-map point panel, upsell) **[gap → platform]**.
  - **Never:** swipe-to-delete (no undo), swipes on map surfaces, swipe between Trasy segments (they are separate routes), swipe that changes the bottom tab.
  - **Conflict rules:** a map owns every drag inside it; the deepest horizontal scrollable wins inside its own box (chip rail, carousel, photo pager, calendar beat segment swipe and the bike pager); vertical scroll wins when |dy| passes the slop first; the iOS left 20 px edge always belongs to back.
- **G5 Vertical.** Pull-to-refresh ONLY where a refresh/retry action already exists (V21 §2.5 "brand spinner"; Profil hub; lists Motorky, Rezervace, Zprávy; e-shop grid; payment methods): Android neon disc, iOS adaptive Cupertino spinner in neon; under a dark header the iOS rubber-band shows the header colour, never the canvas. Drag on a form scroll hides the keyboard.
- **G6 Zoom** only in photo viewers: pinch 1–4×, double-tap 1× ↔ 2.5× (300 ms `MgMotion.out`); page swipe and swipe-down dismiss (100 px / 800 px/s = today's app values) only at scale ≤ 1.01.
- **G7 Long-press** = tooltip / large-content bubble only (nav labels, icon-only buttons; V2 §4.1, V22 §6.1); never an action.
- **G8 Haptics:** `selectionClick` for press, selection, committed swipe / snap / month (V2 §1.3); `heavyImpact` only for the SOS entry pill (V2 §4.3); legacy `lightImpact` of the old toast helper stays. Nothing else.

## M · Motion (tokens = `MgMotion`, v1 §2.7)
- **M1 Transitions by navigation kind:**
  - tab switch: fade-through `tab` 210 ms (incoming fade + scale .98→1) instead of no transition (v1 §2.7, §4.1);
  - push (pushed screens, focused flows, details): platform route transition ≈ 300 ms (iOS Cupertino with edge-back, Android predictive back); the nav slides out/in 110 % over `sticky` 300 emphasized (V2 §4.1). v1 `push` "slide-up 24 px" is NOT used: it would disable the iOS edge-back (owner R6 wins);
  - shared element (Hero, `hero` token, radius 16 → 0): `moto-img-{id}` catalog card / Home funnel → bike detail, `res-img-{id}` Home ticket / reservation list card → reservation detail (V2 §5.3, §5.11, §6.3); only inside the shell navigator, never into `/success` (v1 §9); one tagged source per route;
  - sheet: in 300 emphasized / out 250, scrim `night@.55` (v1 `sheet`, V22 §5.2); dialog: fade + scale .96 → 1 in 180 ms (V22 §5.2); viewer: fade 180 over black;
  - in-place content switch (segment, month, sibling, edit intent): 24 px directional slide + fade, `tab` 210 emphasized (`MgSwipeSwitcher`; state-keeping variant `MgStepFade`) **[gap → platform]**; mode / state cross-fade `enter` 450 (V21 §3.1).
- **M2 Entrance:** sections `reveal` 550 ms / 16 px / 70 ms stagger (cap 5) on first build per session (v1 §2.7, V2 §1.2, §5.11); detail sheet up 450 after the photo (V2 §6.3); Ken Burns 8 s ONE-SHOT on hero photos, never infinite (V2 §1.2).
- **M3 Micro-interactions:** selection / ✓ / chip / badge `pop` 300; totals `bump` 450 + delta chip, `scanOnce` on a calculator total — prices never count up (V2 §1.2); `strike` 300 for a price made free by rank; count-up 700 ms once per session only for personal non-price stats (V2 §1.2, V21 §2.5); disclosure `AnimatedSize` 300 + chevron 180° over `color` 180 (V2 §6.3, V22 §5.2); calendar: start `pop`, band grows 300 ms ease, 20 ms per cell, capped 200 ms, summary chip `bump` (V22 §3.6); error = one shake 4 px / 300; recorder dock idle ↔ live morph 300 (V22 §4.3); nav: pill spring + liquid stretch, label colour 180, active icon `pop`, re-tap = scroll top + 3 px nudge (V2 §4.1); AI FAB rest / lift / peek / off 300 spring / 150 (V2 §4.2); status strip, docks, T4 strips slide 300 `sticky` (v1 §2.7, V22 §5.2).
- **M4 Success / pending:** ✓ path draws 300 → disc `pop` → one neon ripple 700 (V22 §5.2); pending ring sweep 1.2 s = the screen's live loop, closes into ✓ in 450 when the state turns success; level-up celebration untouched.
- **M5 Loading:** skeleton in the final layout's geometry (no jump when data lands), shimmer 1.2 s while loading; skeleton → content cross-fade 180; photos fade in 150; spinners only inside buttons (V22 §5.2) and pull-to-refresh; > 15 s → "trvá to déle" + retry (existing `MgLoadingView`).
- **M6 Loop budget:** ≤ 2 infinite loops per screen = the one primary CTA fx + one live indicator (ping / scan / recording dot / pending ring) (v1 §0.6, V2 §1.3); every loop in a `RepaintBoundary`, paused (TickerMode) when off-screen, covered or app not resumed (v1 §2.7).
- **M7 Reduced motion** (`MgMotion.reduced`): every animation snaps to its end state; loops, Ken Burns, Hero, count-ups off; Android page transitions off (iOS keeps the Cupertino transition because it carries edge-back); sheets / dialogs without animation; swipes commit on release without following the finger; paths drawn complete (v1 §2.8, V2 §2.6, V22 §1.3). Route navigation: no decorative motion at all (v1 §2.8).

## D · Display
- **D1 Surfaces (V22 §2.1–2.3):** canvas `#F4F7F5` pages, white cards, `well` tiles / inputs in cards; ≤ 1 dark block per 746 px window besides chrome; dark header + hero overlap −24; light sheets; chrome (nav, FAB, docks, toasts, strips) dark; budgets R5.4; exempt = photo / map / live screens, SOS red system.
- **D2 Rank (V22 §1.4):** rank material only on dark carriers (primary CTA, header aura, nav pill, FAB ring, success / pending hero); on light only ring / emblem / progress / dark chip with dot; rank text on light = ink; never on prices, ✓/⚠/✕, SOS, links, Pay buttons.
- **D3 Actions:** one primary per screen (v1 §0.1); on light `btnInk` / `btnGhostLight` / `btnText` (R5.8); a rank CTA inside a light area sits in a dark dock; destructive `#B42318`; SOS `#D92D20`; T6 safe left / action right, stacked when a label does not fit; buttons never ellipsize and show their spinner inside.
- **D4 Type & copy:** Montserrat; screen title 22/800, sheet / dialog 20/800, bar title 17/800 one line else 15/800 on two lines (V22 §6.1); body 14/600; meta ≥ 11/700 `#55705F` on light, `#9FC4B1` on dark (V22 §2.2); prices and counters tabular; `MgWordFit` (never a mid-word break, never an ellipsis on a title or button); NBSP before the currency and inside "3 dny"; locale number format ("1,2 km", "12 027 Kč"); dates "pá 23. 10. → ne 25. 10." (year only when not the current one); tykání + gender-neutral, other languages informal where it exists (V22 §5.3); ≤ ~12 words of prose per block (v1 §0.2); no emoji in UI (v1 §2.9, V22 §5.3).
- **D5 Icons:** `MgIcon` 24-grid line icons; tone icons per V22 §5.2.
- **D6 Images:** every network photo through `MgImage` / `MgPhoto`: server thumb + `memCacheWidth`, fixed aspect box, placeholder `well` + glyph on light / `panel #0E2A1C` on dark (no light flash on dark), fade 150 (0 when reduced), error = same box + glyph.
- **D7 Disclosure (owner 2026-10-16):** always visible and expanded: dates, bike, branch + type (samoobsluha / s obsluhou) + address, price / total, what to do next, codes on pickup day, required inputs, blockers, the key sales offer. Collapsed by default (one tap, `MgDisclosure`): optional extras, secondary details, long texts, "Technické detaily". A collapsed section that holds a blocker auto-expands.
- **D8 States = T1–T6 only (V22 §5.2):** errors that need action are T1 / T2 / T3, never a toast (§5.1 #5); T5 toast = confirmation only (2.8 s, 4 s with action; text full width, action after the text); every state: what · why · how + a working action + back / close; raw text only under "Technické detaily ▾"; no support row in payment errors (owner D5).
- **D9 Chrome:** the AI disc never covers a CTA, SOS or money fact (`MgFabAvoid` cta / sos / tap / keep, V2 §4.2); one status strip + "+n" (v1 C2, V2 §4.4); scroll bottom pad = obstruction + 56 + 24.
- **D10 Density:** 16 px gutters, 12 px card gaps, ≥ 44 px targets; every text fits 320 / 360 / 412 dp in 8 languages at text scale 1.0 and 1.3 (render matrix + fit tests).
